# BuyUadvice

Business compliance and advisory platform — company registration, GST, MCA compliance, trademark, FSSAI and allied services — with a React SPA frontend and a plain-PHP MySQL backend.

- **Frontend:** `frontend/` — React 19 + Vite + Tailwind CSS 4 + React Router 7 SPA
- **Backend:** `backend/` — Plain PHP 8 (no framework) JSON API + PHP session auth + MySQL (PDO) + PHPMailer OTP mails
- **Deploy artifact:** `backend/` itself — upload its **contents** to shared hosting (`public_html/`)

## Features

**Frontend pages (`frontend/src/pages/`):**
- `/` Landing, `/about`, `/services`, `/services/:id`, `/partner`, `/contact`
- `/terms`, `/privacy`, `/dashboard` (authenticated)
- Shared `Navbar`, `Footer`, `Cta`, `Faq`, `PageHeader`

**Backend:**
- CORS + credentials handling, `OPTIONS` preflight support
- Session auth (`backend/config/session.php`, HttpOnly `Lax` cookie, 24h lifetime)
- Password hashing with `password_hash()` / BCRYPT
- OTP storage in `otp_tokens` table, SMTP mail via PHPMailer

## Prerequisites

- Node.js 18+ and npm
- PHP 8.0+ with `pdo_mysql` extension (uses `str_starts_with`, typed PDO)
- Composer
- MySQL / MariaDB
- For Windows deploy script: PowerShell 5.1+ (`robocopy` is used)

## Getting Started (Local Development)

### 1. Database

```bash
# create the DB first, then import tables:
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS buyuadvice_latest;"
mysql -u root -p buyuadvice_latest < backend/sql/schema.sql
```

This creates (see `backend/sql/schema.sql`):
- `users(id, name, email UNIQUE, phone UNIQUE, password, google_id, avatar, created_at, updated_at)`
- `otp_tokens(id, identifier, otp, expires_at, created_at)`

> `backend/config/database.php` reads `DB_HOST/DB_NAME/DB_USER/DB_PASS` from `backend/.env`
> (local defaults: `localhost` / `buyuadvice_latest` / `root` / empty). The name you import
> into must match `DB_NAME` in `backend/.env`.

### 2. Backend setup

```bash
cd backend
composer install
```

Create `backend/.env`:

```env
DB_HOST=localhost
DB_NAME=buyuadvice_latest
DB_USER=root
DB_PASS=

GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret

SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SECURE=tls
SMTP_USERNAME=you@example.com
SMTP_PASSWORD=your-app-password
SMTP_FROM_EMAIL=noreply@buyuadvice.com
SMTP_FROM_NAME=BuyUadvice
```

Run locally (single command, single port — frontend + backend on :8000):

```bash
# from repo root:
php -S localhost:8000 -t backend backend/router.php
# or:
cd backend
php -S localhost:8080 router.php
```

Open `http://localhost:8080/` — `/` + SPA routes serve the built frontend copy inside
`backend/`, `/backend/*` serves the PHP API. Backend `.php` edits apply on refresh.
After editing the frontend, run `npm run build` in `frontend/` (auto-syncs `dist/` into
`backend/`) and refresh — no second server needed. `npm run dev` (Vite HMR on :5173)
is optional and only for hot-reload frontend work; it is not required.

### 3. Frontend setup

```bash
cd frontend
npm install
npm run dev
```

Create `frontend/.env`:

```env
VITE_GOOGLE_CLIENT_ID=your-google-client-id.apps.googleusercontent.com
```

Scripts (`frontend/package.json`):

| Command | Description |
|---|---|
| `npm run dev` | Vite dev server with HMR (optional, frontend-only) |
| `npm run build` | Production build to `frontend/dist/` + auto-sync into `backend/` |
| `npm run build:only` | Production build without syncing into `backend/` |
| `npm run preview` | Preview production build |
| `npm run lint` | ESLint |

## Environment Variables

**`backend/.env`:**

| Key | Used in | Description |
|---|---|---|
| `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` | `config/database.php`, `.env` loader in `index.php`/`router.php` | MySQL connection |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `auth/google.php` | Google OAuth client |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL`, `SMTP_FROM_NAME` | `config/smtp.php` | PHPMailer OTP mail |

**`frontend/.env`:**

| Key | Description |
|---|---|
| `VITE_GOOGLE_CLIENT_ID` | Google Identity Services client ID |

Never commit real `.env` values. Both `frontend/.env` and `backend/.env` already exist locally — keep them out of version control for production secrets.

## Build & Deployment (Hostinger / Apache)

`deploy.ps1` verifies the shared-hosting upload:

```powershell
.\deploy.ps1
```

It runs `npm run build` in `frontend/` (which auto-syncs `dist/*` into `backend/`),
then checks `backend/` contains `index.html`, `index.php`, `.htaccess`, `auth/`, `config/`, `vendor/`.

Upload the **contents** of `backend/` (not the folder itself) to `public_html/`:

- `/index.html`, `/assets/*`, `/heroimages/*`, `/servicesimages/*` → React app
- `/index.php`, `/auth/*`, `/config/*`, `/vendor/*` → PHP API (reached via `/backend/*` URLs)
- `/.htaccess` → required for routing + source protection
- Do NOT upload `router.php`, `composer.json/lock`, `.gitignore`, `sql/` is only for the one-time DB import

`backend/.htaccess` behavior:
- `/backend/*` non-file requests → `/index.php`
- Direct `/auth/*`, `/config/*`, `/vendor/*`, `/sql/*`, `/.env`, `/router.php` → forbidden
- All other non-file/non-dir requests → `/index.html` (React Router fallback)
- `/` serves `index.html` (`DirectoryIndex`), not `index.php`

Database (once per hosting account):
1. hPanel → create MySQL database + user
2. phpMyAdmin → Import → `backend/sql/schema.sql` (creates `users`, `otp_tokens`)
3. Set production `DB_*` (+ SMTP + Google) in `backend/.env` before uploading

## Troubleshooting

- **404 on `/backend/*` in production:** `backend/.htaccess` missing (upload it — dotfiles are hidden in some FTP clients) or `mod_rewrite` disabled; verify you uploaded the *contents* of `backend/`, not a `backend/` subfolder.
- **Blank page on refresh of `/services/...`:** SPA fallback `.htaccess` rule missing.
- **Session not persisting:** frontend `fetch` must use `credentials: 'include'`; backend CORS `Access-Control-Allow-Credentials: true` requires a specific `Access-Control-Allow-Origin` (not `*`) — `index.php` echoes `HTTP_ORIGIN`.
- **OTP mail not sending:** check `SMTP_*` in `backend/.env`, Gmail App Password, and `vendor/` presence on host.
- **Google login popup closes with error:** mismatched authorized redirect URI — must include `https://<your-domain>/backend/auth/google.php` in Google Cloud Console, plus matching `GOOGLE_CLIENT_ID/SECRET` and `VITE_GOOGLE_CLIENT_ID`.
- **DB connection fails:** verify `DB_*` values and that `buyuadvice_latest` (or your DB name) is imported from `sql/schema.sql`; note local default DB name in `config/database.php` vs `schema.sql` (`buyuadvice`).
